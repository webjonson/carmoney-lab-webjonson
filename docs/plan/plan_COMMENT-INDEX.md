## Контекст

`backend/public/index.php` — единая точка входа HTTP (docroot), 9 строк:
`declare(strict_types=1)`, `use CarMoneyLab\AppFactory`, `require` автозагрузчика
Composer и запуск Slim-приложения. Комментария, объясняющего роль файла, нет.
Соседний `backend/public/router.php` (строки 5–8) уже оформлен в принятом
стиле: русскоязычный docblock после `declare(strict_types=1);`.

## Файлы

- `backend/public/index.php` — единственный файл изменения: добавить
  docblock-комментарий между строкой 3 (`declare(strict_types=1);`) и
  строкой 5 (`use CarMoneyLab\AppFactory;`), с пустыми строками до и после.

Всё, чего нет в списке, при реализации трогать нельзя.

## Шаги

1. В `backend/public/index.php` после `declare(strict_types=1);` (строка 3)
   добавить docblock в стиле `router.php`. Предлагаемый текст (черновик,
   ждёт подтверждения заказчиком):


2. Больше ничего в файле не менять: `use`, `require` и
   `AppFactory::create()->run();` остаются как есть, кодировка UTF-8,

3. Прогнать проверку из раздела «Тесты».

## Тесты

- Новых тестов нет: комментарий не меняет поведение,PHPUnit трогать не нужно.
- `make lint` — `php -l` по `backend/` должен пройти без ошибок синтаксиса.
- `make test` — по желанию, как контрольная точка; изменений логики нет.
- `curl http://localhost:8080/health` — приложение стартует и отвечает
  (комментарий не должен влиять, проверка дешёвая).

## Риски

- Риск низкий. Единственный реальный способ сломать файл — разместить текст
  ДО открывающего `<?php` (любой вывод до тега нарушит HTTP-заголовки)
  или случайно задеть строки 5–9 при вставке.
- Комментарий должен оставаться описательным и синтетическим: без
  реквизитов, имён и ссылок на реальные данные (правило проекта).
- На `router.php` изменение не влияет: он делает `require __DIR__ . '/index.php'`,
  комментарии при подключении файла безвредны.
